# openai-rs 0.2.0 扩展计划

## 目标

将当前已完成的 Responses API 实现作为基线，扩展尚未发布的 0.2.0 范围，覆盖 OpenAI 当前稳定、面向普通项目 API key 的公开 API，并改进文件传输、WebSocket、分页、超时和安全重试能力。0.2.0 完成全部验收后再打 tag；本计划不再调整包版本号。

接口范围以更新后的 OpenAI 官方 OpenAPI 快照及官方 API 文档为准：只纳入正式发布且仍可用的操作；排除组织/项目管理 API、Agents/Codex 专属 API、beta/legacy 操作，以及已退役或在实现前确定关闭的产品 API。具体排除 Assistants/Threads、旧版 Completions、Evals 和 Videos。Assistants 已于 2026-08-26 关闭；Evals API 计划于 2026-11-30 关闭，Videos API 已于 2026-09-24 关闭。[OpenAI API deprecations](https://developers.openai.com/api/docs/deprecations)

## API 与客户端

- 扩展固定 OpenAPI 快照的提取与代码生成，生成代码按 API 家族拆分。客户端采用资源式入口，覆盖 Responses、Chat Completions、Embeddings、Models、Moderations、Audio、Images、Files/Uploads、Containers、Vector Stores、Batches、Conversations、Fine-tuning、Realtime/Live，以及符合上述纳入标准的其他公开 API。Chat Completions 仍受支持并纳入 SDK；文档说明新项目优先使用 Responses。[Responses migration guide](https://developers.openai.com/api/docs/guides/migrate-to-responses)
- 固定 OpenAPI 提交后，生成 `spec/API_SCOPE.json`，逐项记录纳入/排除的 operation ID、HTTP 方法、路径和理由。代码生成与覆盖验收使用该清单，避免因上游规范变化而隐式扩张或遗漏范围。正式 WebSocket 事件类型优先从固定 OpenAPI 中的 Responses、Realtime 和 Live 定义生成；排除其中的 Beta 类型。
- JSON 响应统一保留强类型数据、原始 JSON 和 request ID；未知字段与未知 SSE/WebSocket 事件保留。覆盖 API 文档中的分页、SSE、WebSocket、multipart 上传和二进制内容下载。错误保留 HTTP 状态码、request ID、服务端错误体及 `Retry-After` 上下文。
- 支持正式发布的 Realtime WebSocket 与 Responses WebSocket mode；不实现 WebRTC 媒体栈或 SIP 客户端，不支持 Realtime beta 协议。[Realtime WebSocket guide](https://developers.openai.com/api/docs/guides/voice-websockets) [Responses WebSocket mode](https://developers.openai.com/api/docs/guides/websocket-mode)
  - Responses WebSocket 支持按 `stream_id` 区分并发响应流；Realtime connection 提供双向发送、接收和显式关闭。未知事件保留原始 JSON。连接关闭、握手错误、消费者丢弃流和队列背压都有确定的错误/清理语义；不在已经向调用方交付事件后自动重连或重发。
- 基础 REST 默认可用；WebSocket 和 multipart 使用独立 Cargo features。大型文件下载使用流式接口，公共 API 不暴露 `reqwest` 专用类型。
- 提供可配置连接/请求超时和独立的流 idle timeout；idle timeout 默认关闭，总时限默认不截断长时间生成或流连接。SSE 收到协议终止事件后正常结束，`response.failed` 返回 API 错误；终止事件前 EOF 返回流错误。丢弃 SSE 流会停止底层读取。逐页异步 `Stream` 每项返回完整页，保留 cursor、页级响应和 request ID。
- Responses WebSocket 为每个 `stream_id` 独立路由事件和终止状态；Realtime connection 采用双向事件接口。正常关闭、服务端错误事件、传输错误、idle timeout 和消费者关闭均可区分。使用有界缓冲或直接异步轮询避免无界积压。Codex 中串行化 Responses 请求以及 Codex 专用 Realtime v1/v2/agent handoff 适配仅作参考，不作为本 SDK 的协议限制或公共语义。
- 增加显式 `RetryPolicy`，默认关闭。启用后最多重试 3 次，仅针对连接错误、408、429 和 5xx，解析秒数及 HTTP 日期形式的 `Retry-After`，使用带 jitter 且有上限的指数退避。GET/HEAD 可重试，写请求须提供幂等键；请求体必须可重放。SSE/WebSocket 只允许在首个事件交付调用方之前重试连接建立/握手，不自动重放已开始的流。
- multipart 上传接受可重放的 `Bytes`/文件路径或可重新打开内容的工厂；一次性流可以上传，但不自动重试。下载流被丢弃时取消剩余读取。遵循 OpenAI 公共 Files/Uploads API，不复制 Codex 特有的分阶段上传、内部 use-case 字段或专用下载 URL 流程。
- 更新 README、API 家族示例、Cargo features、超时/重试/分页/流式说明及 0.1.0 到 0.2.0 迁移说明。

## 验收与验证

- `spec/API_SCOPE.json` 中每个纳入 operation 均有生成协议类型与客户端调用入口，每个排除项均有理由；代码生成可由固定规范和固定生成器复现。独立下游 crate 可消费 README 示例，依赖树不包含 Codex 内部 crate。
- 离线检查覆盖请求与查询编码、响应解析、未知字段保留、SSE/WebSocket 事件解析和终止语义、EOF/idle timeout/消费者取消、分页 cursor、重试次数和可重放条件、`Retry-After` 两种格式、multipart 构造、二进制流、背压和错误上下文。测试使用纯协议样例或解析器输入；**不启动本地 mock HTTP 服务或 mock WebSocket 服务。**
- 完成默认与可选 Cargo feature 组合的构建检查、文档示例检查、格式检查和代码生成一致性检查。
- 真实 API smoke 与离线检查分开报告。使用继承的 `DEEPSEEK_TOKEN` 验证 DeepSeek 实际支持的兼容场景；其他端点只有在存在对应 OpenAI 凭据时才做在线验证，否则明确标为未验证。不记录凭据，不以离线检查宣称在线通过。
- 更新本文的实施状态，记录变更、离线验证、真实服务商调用和环境限制。所有验收完成后再创建 0.2.0 tag。

## 当前基线

- 仓库当前已有 Responses HTTP JSON/SSE 创建、检索、删除、取消、输入项分页、token 计数和 compact；类型来自固定 OpenAPI schema，统一 JSON 响应包装为 `ApiResponse<T>`。
- 当前实现及 DeepSeek 创建 JSON/SSE smoke 作为既有基线，不代表本计划新增 API 或在线场景已验证。实施时根据新增范围更新此节和验收记录。
